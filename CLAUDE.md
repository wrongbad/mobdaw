# Notes for Claude

- Record hidden foot-guns in `docs/todo.md`: latent bugs or risky shortcuts that will bite later and that nobody will remember otherwise. Say what it is, where it lives, and the fix. Don't log routine follow-ups, "check this in a browser" items or feature ideas there. Remove an entry once it's fixed.
- Tests while iterating: run only what the change touches. Use `npm run test:changed` (client tests that import the changed files), `npm run test:dsp-core` (the `dsp` crate) or `npm run test:engine` (the `engine` crate), or a single test file. Run the full `npm test` (which includes the SLOW tests) once, at the end of a piece of work. Gate new tests that take seconds behind `SLOW=1` (vitest: `describe.runIf(process.env.SLOW)`); long sweeps such as calibration are tools, not tests.
- Don't lose long work. Tools that run for minutes (sweeps, benchmarks, renders) write their results under the repo in `docs/<topic>/runs/<date>-<label>/`, not `/tmp` or only the console. That tree is git-ignored except small summaries (`*.md`, `verify.txt`, `config.yaml`, `best.json`, `run.sh`): write a `fit.md`/`report.md` with the conclusions and commit that, never CSV/SVG/WAV/jsonl. Raw data is not backed up by git, so don't delete it casually. Commit work in progress at each checkpoint (`wip: …` commits are fine) instead of leaving it uncommitted until the end; an agent can be stopped at any time.
